# Role guides and training plan

Status: Draft. Owner: Training/change-management lead. These are role-based task outlines; add screenshots and localized instructions only after the UI stabilizes. Use synthetic demonstration data.

## Branch administrator

Find an existing member before creating a draft; assign the correct branch; enter only required details; submit for approval; respond to rejection/correction; request transfer instead of changing branch directly. Never create a login to bypass approval. Report suspected duplicate or unauthorized access.

## Approver and new-member coordinator

Review submitted snapshot and branch context; decide with reason; do not approve your own submission if separation policy requires it. Assign published curriculum, buddy and iMihlangano; review unmet requirements and exceptions; graduate only under Church policy.

## Finance user

Choose assigned branch, fund, period and currency; capture manual entries; confirm offline sync; validate batch; post once; reconcile receipts/provider settlements; correct posted data through reversal/adjustment. Never use browser payment success as proof of settlement.

## Pastoral/prayer user

Use only explicitly assigned cases; keep notes factual and minimal; respect classification and child protections; use approved escalation; never forward confidential narrative in ordinary messages. Access is logged.

## Member

Register in person at a branch, privately secure the account after approval, view own profile/journey/giving, request controlled changes, manage communication preferences and report an error. Household access is not assumed. Online giving receipts may remain pending until provider confirmation.

## Training rollout

Pilot one branch per country when countries are known; train local champions; provide short scenario exercises and a support contact; verify understanding with UAT tasks. Translate key labels and privacy notices as approved. Refresh training after material policy or UI changes.
